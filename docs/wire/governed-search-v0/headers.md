# Governed HTTP headers (`room-v1`, `multi_room=closed`)

Header names are case-insensitive. This describes direct daemon HTTP, not what a gateway forwards or adds.

## Requests

| Route | Required application headers |
|---|---|
| `POST /v0/search` | `Authorization: Bearer <capability>` (literal, case-sensitive `Bearer ` prefix; see [capability.md](capability.md)). `Content-Type: application/json` (Axum also accepts `application/*+json` and media-type parameters). |
| `GET /v0/health` | None. No credential, request body, or `Content-Type` required. |

No `Accept` header is required. Transport headers such as `Host` and request framing follow the HTTP version in use. The daemon does not require room-format headers on a request.

## Responses

| Header | When present | Values and meaning |
|---|---|---|
| `Content-Type` | Both routes, success and JSON errors | `application/json` |
| `Kwiry-Id-Scheme` | Every application response at `/v0/search`, including auth, request, search and method errors | `room-v1` |
| `Kwiry-Multi-Room` | Same as `Kwiry-Id-Scheme` | `closed`; repeated vault IDs per capability are not admitted (multiple distinct vault/room tuples are allowed). |
| `WWW-Authenticate` | `401 unauthorized` | `Bearer` |
| `X-Kwiry-Index-Freshness` | Search 200 only | `<state>; basis=<basis>`: `current`, `stale`, or `reconciling`; `strict_hash` (default) or `metadata_audit`. `stale` and `reconciling` may serve hits but are not proof of current source contents. `unavailable` is not a successful governed state, and `producer_manifest` is not an accepted configuration. |
| `X-Kwiry-Generation` | Search 200 only | `v1-` followed by exactly 64 lowercase hex digits. This is a digest of the **effective resource set** and its served revisions, including a defined digest for an empty set. It is not the global generation ID, a resource ID, or `extraction_policy_fingerprint`. |
| `X-Kwiry-Lexical-Profile` | Search 200 only | `lexical-v2` |
| `X-Kwiry-Lexical-Match-Quality` | Search 200 only | `standard_only`, `mixed`, `partial_only`, or `none`, describing standard vs. partial lexical evidence. `not_applicable` is not emitted on governed search. |
| `X-Kwiry-Field-Scope` | Search 200 only | `none`, `name`, `filename`, `title`, `alias`, `heading`, `tag`, or `body`; effective `in:<field>` control. |
| `X-Kwiry-Field-Emphasis` | Search 200 only | Same vocabulary as field scope; effective `><field>` control. |
| `Allow` | Framework response on a method mismatch, even if capability verification fails first | `/v0/search`: `POST`; `/v0/health`: `GET,HEAD`. |
| `Content-Length` | HTTP framing for these fixed-length responses | Decimal length in bytes. For `HEAD`, the body is suppressed, but the corresponding length can still be sent. |
| `Date` | Automatically generated by the HTTP server | Response time as an HTTP date (GMT). |
| `Connection` | HTTP/1.x framing when an explicit connection directive is needed | `close` when closing (as in the HTTP/1.1 fixtures), `keep-alive` when explicitly keeping an HTTP/1.0 connection alive; otherwise may be absent. |

`GET /v0/health` does **not** carry the room-format, freshness, generation, or lexical headers; its JSON contains `id_scheme` and `multi_room`. The framework also answers `HEAD /v0/health` with no body. Requests rejected by the transport before routing are outside these application rules.
