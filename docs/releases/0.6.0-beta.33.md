# kwiry-search 0.6.0-beta.33

This release adds a bounded best-attempt search for long exploratory keyword queries, truthfully labels partial lexical results, and removes the in-flight count from the Obsidian status bar while preserving detailed indexing progress in the search modal.

## Exploratory lexical search

Short and ordinary searches remain precise. When a fully supported ordinary query contains at least four useful optional terms and every stronger authorized lexical lane returns zero candidates, shared Rust may run one bounded partial-coverage pass. Required identifier anchors remain mandatory, while the useful optional terms are evaluated as alternatives and at least one must match.

The fallback is a single bounded stage rather than a combination search or power-set expansion. Native Tantivy and in-plugin FTS5-WASM consume the same Rust-authored policy, candidate ceilings, authorization filters, proof classes, and final ranking. Filename, title, and alias evidence retains its metadata priority, while greater term overlap can rank higher within the same evidence field.

## Result disclosure and diagnostics

Results selected from the exploratory stage are labeled as best-attempt partial matches. Mixed standard and partial result windows are labeled separately. Daemon and in-plugin execution carry the same closed lexical match-quality fact without changing the frozen daemon JSON response body.

Diagnostics record only closed categorical match quality and bounded aggregate execution evidence. They do not record query text, terms, source identities, paths, excerpts, SQL, raw plans, arbitrary backend messages, credentials, or tokens.

## Status bar

The Obsidian status bar no longer displays the in-flight count. Detailed background-index progress in the search modal still includes the count. The persistent status element retains fixed whole-item geometry, complete `title` and `aria-label` text, overflow behavior, and duplicate-write suppression.

## Compatibility and migration

The internal lexical query-plan schema advances to 10 and the FTS5 match-plan schema advances to 9. Worker protocol 16, cache schema 12, persisted index layout, source preparation, format identities, public search response bounds, and mode behavior remain compatible. No migration is required; disposable cache data remains valid.

## Verification

Verification covers native and portable Rust profiles, Tantivy and FTS5 lexical conformance, standalone native/WASM byte parity, authorization-before-retrieval, bounded candidate collection, partial-result ranking and disclosure, daemon headers, worker and backend propagation, diagnostics privacy, production packaging, and a pinned real-Obsidian Selenium gate. The real-host gate confirmed zero status or sibling movement while in-flight values changed and emitted aggregate-only evidence.
