# kwiry-search 0.6.0-beta.26

This release makes grouped source navigation predictable, exposes the current Sources/Sections level, and reduces visual competition inside the search modal.

## Source rows open the source

A grouped source row previously reused its highest-ranked section as both its preview and navigation target. Pressing Enter could therefore jump to a heading, Base view, or PDF page even though the user had selected the source-level row.

Source rows now open the source generally. The representative section still provides ranking and the preview excerpt, but it no longer chooses the source-level open location. After drilling into returned sections, selecting an explicit section still opens its exact Markdown heading, Base view, PDF page, or file.

The same distinction applies to current-leaf, new-tab, new-split, background-tab, and mouse opens. Existing stale-result, backend-instance, vault-mapping, path, and missing-file checks remain unchanged.

Alt+Enter remains note-link insertion. Alt+Shift+Enter retains its existing section-link behavior.

## One Sources/Sections toggle

Ctrl+L is now the primary level toggle:

- from Sources, it shows the selected source's already returned sections;
- from Sections, it returns to Sources and restores the selected source.

Ctrl+H remains a compatibility shortcut for returning to Sources, but it is no longer presented as a required second half of the workflow. A compact context label says whether the modal is showing `Sources` or `Sources › Sections in …` and names the current Ctrl+L action.

Changing the query or requested mode still exits the local section projection and performs a normal global search. Drilling into sections is not source-scoped search: it only projects the matching sections already present in the bounded global response.

## Compact backend and mode context

The separate backend-capability line and `Requested mode` row are replaced by one compact context bar:

- lexical-only profiles render static text such as `In-plugin · Lexical`;
- a multi-mode daemon retains the accessible Lexical/Semantic/Hybrid segmented control;
- an unavailable active daemon remains explicitly labeled unavailable.

This does not probe or switch to an inactive backend. Backend selection remains explicit in Settings, with no silent fallback. Existing fresh-install and stored defaults are unchanged: Daemon remains the fresh profile default, Hybrid remains its preferred mode, and In-plugin remains lexical-only.

The two-line query and indexing status rail remains separate so its live-region behavior and stable height are preserved.

## Clearer result hierarchy

Result rows now reserve their strongest treatment for the source title and format chip. Source rows show the source path without appending the representative heading as though it were the open target. Path and returned-section metadata share a smaller muted details line, excerpts are quieter, and highlighted terms remain prominent and readable.

Obsidian continues to own selected and hovered row backgrounds. Counts remain limited to sections observed in the returned search window and are not promoted into corpus totals.

## Compatibility

This patch does not change ranking, grouping, extraction, source formats, query scope, or persisted/index transport contracts:

- Worker protocol remains 13;
- plugin cache schema remains 12;
- source-preparation schema remains 10;
- HTML extractor identity remains version 2.

No forced reindex is required.

## Verification and publication boundary

Automated coverage includes source-versus-section targets across formats and placements, PDF page behavior, stale validation, Ctrl+L round trips without backend work, compatibility shortcuts, compact backend/mode rendering, result hierarchy CSS, typechecking, privacy validation, production build, and the complete bounded plugin suite.

The real Obsidian WebDriver/X11 candidate gate remains part of the protected release workflow. BRAT publication still requires the immutable candidate handoff accepted by the publisher workflow.

## Install

After the protected candidate and publisher workflows complete, install or update through BRAT using repository `cybersader/kwiry`, or use the release archive attached to `0.6.0-beta.26`.
