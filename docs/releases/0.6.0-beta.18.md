# kwiry-search 0.6.0-beta.18

Beta.18 follows the successful beta.17 field rebuild, which completed 4,561/4,561 sources and reached a ready, searchable, clean index with Excel enabled. It corrects a query-plan validation mismatch exposed by filename-like multi-word searches and replaces unbounded full-report clipboard copying with a bounded summary plus a full sanitized file export.

## Filename-like and identifier searches

Rust legitimately uses an analyzed term as a required identifier anchor for bounded acronym/number fallback and for filename or stem metadata promotion. The TypeScript mirror incorrectly required every such anchor to use the exact-identifier projection, so a valid Rust-authored plan could be rejected before FTS execution as `invalid_query_plan`.

Beta.18 removes only that reversed implication. Exact-identifier projections must still be required anchors, optional exact identifiers remain invalid, and malformed probes, changed bounds, invalid stages, unknown fields, and relaxed required anchors continue to fail closed. Required analyzed anchors stay in the analyzed-text lane; they are not promoted into the exact-identifier FTS constraint.

Rust classification, evidence stages, candidate limits, ranking, query semantics, and the Worker execution translator are unchanged.

## Bounded clipboard diagnostics

**Copy summary** now copies only the readable sanitized report under a strict 65,536-byte UTF-8 ceiling. It never appends the structured JSON records. The report includes retained, dropped, filtered, emitted, and clipboard-omitted counts, and truncation omits complete event lines rather than splitting a UTF-8 sequence or record.

The former persisted compact/full report-detail setting is ignored on load and removed on the next ordinary settings save. A prior full setting cannot restore full-report clipboard copying.

## Full diagnostics file export

**Export full report…** takes one point-in-time snapshot and streams the complete sanitized schema-v1 report through the desktop system save dialog. Records are serialized incrementally in bounded UTF-8 chunks rather than materializing duplicate arrays and one large report string.

The desktop adapter:

- suggests a timestamped `.txt` file in a safe OS-owned location when available;
- requires the selected destination to be outside the active vault;
- refuses canonicalized symlink or junction traversal into the vault;
- creates an exclusive owner-only same-directory temporary file;
- handles partial writes, syncs and closes the completed file, then performs the final replacement;
- cleans an unpublished temporary file after failure;
- treats dialog cancellation as a silent no-op.

Destination paths and underlying filesystem or dialog errors never enter notices or diagnostics. The host reports only fixed outcomes, and Electron/Node filesystem authority remains in the main bundle and outside the Worker graph.

## Compatibility identities

Beta.18 does not change the Worker protocol, query-plan schema, FTS match-plan schema, cache schema or image format, checkpoint formats, source policy, ranking identity, or extractor identities. Plugin-version cache compatibility remains strict, so the normal version update may still reject an older plugin-version cache and rebuild it.

## Verification and acceptance boundary

Automated coverage exercises Rust preparation and metadata-promotion shapes, the exact generated production Worker, retained malformed-plan refusals, one-snapshot diagnostics planning, exact UTF-8 clipboard bounds, incremental structured serialization, cancellation, canonical outside-vault enforcement, partial writes, sync/close/rename ordering, cleanup at injected failure points, legacy settings migration, and main-only desktop authority.

The full plugin and Rust adapter suites remain bounded during local verification to avoid concurrent `wasm-bindgen` saturation and tmpfs pressure. Native save-dialog presentation and an actual outside-vault save still require the short desktop acceptance check in the pinned real Obsidian runtime. Beta.18 does not amend `CONTRACT.md`.
