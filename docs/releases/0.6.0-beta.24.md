# kwiry-search 0.6.0-beta.24

HTML files can now join the same local index as notes, documents, drawings, PDFs, and workbooks.

## Bounded HTML indexing

Kwiry now admits standalone `.html` and `.htm` files. HTML is enabled by default; PDF and Excel remain the only default-off formats.

Rust core parses UTF-8 HTML through a bounded tokenizer and deterministic recovered tree. Searchable primary content includes reader-facing body text, literal headings, list items, table captions and cells, link text, and nonempty image or area `alt` text. The first nonempty `<title>` becomes canonical title metadata once rather than being copied into body text.

Weaker latent evidence remains searchable without receiving title, heading, identifier, tag, alias, or property boosts. This includes the first metadata description, literal `aria-label` text, `<noscript>` fallback text, semantic page chrome, and content explicitly hidden through admitted inline markers.

The extractor does not fetch or dereference anything. Scripts, styles, templates, comments, forms, structured data, resource attributes, URLs, adjacent companion directories, frames, embedded payloads, and referenced files do not become host capabilities or searchable properties. HTML contributes no `links_out`, locator, or Obsidian section links.

Malformed markup within budget is recovered deterministically. Invalid UTF-8 is unreadable, and exceeding any mandatory parser, tree, text, section, heading, table, attribute, or notice budget quarantines the whole source transactionally; no partial indexed prefix survives.

## Honest cache rebuild

HTML changes the transported format set and persisted SQLite schema:

- source-preparation schema 9 → 10;
- plugin cache schema 11 → 12;
- HTML extractor identity begins at version 2;
- the portable extraction-policy and per-format identity mirrors advance with the Rust authority.

Existing schema-11 cache images are rejected rather than migrated in place. The plugin performs one honest whole-vault rebuild after upgrade. This rebuild may also repair a stale generation that had previously omitted an existing file.

Worker protocol remains 13. The closed failure-cause classification introduced by the unpublished beta.23 code is included: failed searches may report `sqlite`, `plan_rejected`, `bounds_exceeded`, or `internal` without transporting the thrown value, SQL, query text, paths, or note content.

## Search behaviour

HTML feeds the existing source-neutral lexical pipeline. Query planning, evidence tiers, BM25 weights, prefix selection, and ranking rules are unchanged. Canonical HTML titles enter the existing title and exact-title lanes; latent content remains ordinary searchable content without structural boosts.

## Known limits

- XHTML is not admitted.
- HTML decoding is UTF-8 only.
- HTML results open the file, but carry no fragment locator or section-link target.
- Stylesheets are never evaluated, so content hidden only by an external or embedded stylesheet remains primary unless another admitted hidden marker applies.
- This release does not resolve every possible stale-index report. If a Markdown file is still absent after the mandatory rebuild, export diagnostics immediately after reproducing it so discovery, preparation, cache, and indexing outcomes can be distinguished.

## Verification and publication boundary

Automated verification covers native and portable Rust extraction; malformed and hostile HTML; parser and live-heap ceilings; native/WASM byte parity; Worker and FTS5 projection; title-only and latent sources; exact cache rejection and cold rebuild; schema and identity mirrors; the generated production Worker; the complete plugin suite on Node 22 and 24; Windows and Linux daemon suites; rebuild-from-nothing determinism; privacy validation; licence, notice, fixed-derived-data, package, corpus, and disposable-vault gates.

The real Obsidian WebDriver/X11 candidate gate remains part of the protected release workflow rather than the local development matrix. Tagging and publication require the immutable candidate handoff produced by that gate.

## Install

After the protected candidate and publisher workflows complete, install or update through BRAT using repository `cybersader/kwiry`, or use the release archive attached to `0.6.0-beta.24`.
