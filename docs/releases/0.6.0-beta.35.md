# kwiry-search 0.6.0-beta.35

This release broadens bounded sparse recall for ordinary multi-term queries while preserving standard-result priority, tightens prefix-vocabulary scoping, and clarifies extraction status.

## Prefix-aware sparse recall

A fully supported ordinary query with at least two useful optional terms may now declare one bounded partial-coverage stage. The stage executes only when authorized standard lanes produce fewer than 20 distinct qualified sources; exactly 20 standard sources suppress it. A single optional term does not add a redundant fallback.

Required identifier anchors remain mandatory. Each optional term reuses its canonical bounded prefix-expansion group when one exists and otherwise uses its analyzed exact form. The fallback remains one flat alternative group requiring at least one match, with no subset enumeration or unbounded expansion.

## Standard-first ranking

Internal rank schema 2 places every standard proof and candidate before partial-coverage proofs and candidates, independent of field emphasis. Existing integer evidence points and fixed emphasis continue to order candidates within each class. A candidate carrying both classes selects its strongest standard proof.

Execution lanes follow the same class boundary, so the sparse-result gate observes all standard sources before any partial lane can run.

## Scoped prefix discovery

Prefix vocabulary lookup is now limited to the fields declared by the shared query plan. Missing, duplicate, stale, or out-of-scope field declarations fail closed instead of widening the scan.

## Status clarity

Background status now distinguishes partial extraction from partial query matching and uses source-neutral omission wording across every supported format.

## Compatibility and migration

The internal lexical query-plan schema advances to 12, the constrained-host match-plan schema advances to 11, and the lexical-v2 rank schema advances to 2. Worker protocol 16, cache schema 12, source-preparation schema 10, chunking version 2, persisted index layout, format identities, and public daemon response bodies remain compatible. No content reindex or cache rebuild is required.

## Verification

Verification covers all nine supported source formats from compact raw preparations through native and portable retrieval, deterministic rebuild and restore behavior, standard-before-partial ordering, field-scoped prefix discovery, stale-schema rejection, exact native/portable parity, full daemon and plugin gates, privacy and release packaging, and a fresh real-host interaction gate with zero observed layout shift.
