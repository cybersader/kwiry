# kwiry-search 0.6.0-beta.15

This corrective release fixes result selection in desktop Obsidian's real close-before-choose modal lifecycle. It supersedes beta.14, whose automated modal harness did not model that host ordering and could still label a valid result as out of date when clicked.

## No index rebuild

Beta.15 does not change the plugin cache schema, Worker protocol, source-preparation schema, ranking contract, or Rust extractor identity. Users updating from beta.13 or beta.14 keep their existing disposable index and do not pay another rebuild solely because of this update.

## Result clicks in desktop Obsidian

Desktop Obsidian retains the selected result, closes its `SuggestModal`, and only then calls the selection handler. Kwiry previously discarded the result projection during that close, so the retained result could fail its current-result validation before file opening began.

Beta.15 preserves the projection only for the synchronous foreground-selection transaction. It invalidates it immediately after the selected action is handled. This allows current results to open while preserving the genuine stale-result protections:

- a later index generation still invalidates old rows;
- query, mode, backend-instance, and vault-identity changes remain fail-closed;
- a normal dismissal without a selection invalidates immediately;
- superseded search responses cannot replace the current projection;
- daemon execution generations remain conservative;
- background open and drill-in behavior remain unchanged.

The beta.14 in-plugin generation handoff remains in place: the exact active Worker generation that served a current search is authoritative before the modal's status poll catches up.

## Excel opening

Excel sheet/cell coordinates remain display and storage metadata only. Opening `.xlsx` and `.xlsm` results remains file-level, with no promise of in-workbook sheet or cell navigation.

If Obsidian rejects a result file, Kwiry continues to show only the fixed safe Notice:

> Kwiry: Obsidian could not open this file.

Raw provider errors, paths, workbook names, stacks, and private content are not included in the Notice.

## Real Obsidian WebDriver verification

The original beta.14 build and the corrected candidate were exercised through Selenium WebDriver against the actual Fedora Obsidian Flatpak, not a simulated DOM:

- Obsidian core 1.13.7;
- Electron 43.1.1;
- Chromium and matching official ChromeDriver 150.0.7871.114;
- Selenium WebDriver 4.39.0;
- the disposable Excel test vault and real `.xlsm` fixture;
- native WebDriver mouse selection of the `macro boundary` result.

Beta.14 reproduced the defect: the modal closed, the stale Notice appeared, and `openFile` was never invoked.

The corrected candidate passed the same flow: the expected `.xlsm` row rendered, a native click closed the modal, no stale Notice appeared, `openFile` was invoked exactly once, and the real host promise resolved.

## Automated verification

The correction also passed:

- 1,061 Obsidian tests with one existing skip;
- TypeScript typechecking;
- privacy, licence, notice, corpus, deterministic-build, package, and diff-hygiene validation;
- 16/16 Gate 5 evidence checks;
- Linux and Windows Rust CI;

The modal harness now models desktop Obsidian's real `close → onClose → onChooseSuggestion` ordering so this lifecycle cannot silently regress behind a simplified fake again.
