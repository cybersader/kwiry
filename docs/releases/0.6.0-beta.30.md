# kwiry-search 0.6.0-beta.30

This release preserves fixed search-failure classifications in sanitized diagnostics instead of replacing otherwise valid terminal records with `diagnostic_annotation_rejected`.

## Search-failure evidence

The Worker already classifies query-execution failures into four closed categories:

- `sqlite`
- `plan_rejected`
- `bounds_exceeded`
- `internal`

Three of those categories were present in the TypeScript diagnostics contract but missing from its runtime text-value allowlist. When a failed search carried one of the missing values, atomic diagnostics validation correctly failed closed but discarded the actionable terminal classification.

Beta.30 completes the runtime allowlist. Failed search records can now retain the fixed code, stage, retryability, and cause required to distinguish database rejection, plan refusal, bounded-limit failure, and an internal fallback. Arbitrary causes and free-form error details remain rejected.

## Privacy and compatibility

The diagnostics privacy boundary is unchanged. Reports still exclude raw queries, source identities, paths, excerpts, content, SQL, raw execution plans, arbitrary backend messages, stacks, credentials, and tokens.

This release does not change search execution, query binding, ranking, candidate collection, Worker protocol, diagnostics schema, cache schema, source identity, chunk identity, extraction behavior, or persisted index storage. No manual reindex or migration is required; versioned disposable cache data may rebuild under the existing upgrade behavior.

## Verification

Automated coverage exercises all four fixed failure categories through terminal diagnostic capture and export. Protocol tests accept exactly the closed cause vocabulary, reject unsupported values and extra fields, and verify classification without retaining thrown messages. Existing privacy rejection, full-report export, Node 22/24 Gate 5 lifecycle, package, and real-host release gates remain in force.
