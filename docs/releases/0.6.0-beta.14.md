# kwiry-search 0.6.0-beta.14

This corrective release makes current in-plugin search results immediately actionable when an index publication completes just before the search modal's status poll observes the new generation.

## No index rebuild

Beta.14 does not change the plugin cache schema, Worker protocol, source-preparation schema, ranking contract, or Rust extractor identity. Users updating from beta.13 keep their existing disposable index and do not pay another rebuild solely because of this update.

## Current results no longer appear stale

The in-plugin Worker serializes publication and search and reports the exact active generation that served each query. The modal now accepts that generation for the current successful in-plugin execution instead of waiting for its 400 ms status poll to catch up.

This fixes the false message:

> Kwiry: these search results are out of date. Wait for the refreshed results.

The genuine stale-result protections remain in place:

- a later status generation still clears old rows and reruns the retained query;
- an older superseded query cannot replace the current projection or advance its generation;
- daemon results remain conservative because their execution generation is not yet sourced from the authoritative response header;
- backend-instance and vault-identity checks remain unchanged.

## File opening

Excel result locators continue to record the matching sheet and A1 cell for display and storage only. Opening `.xlsx` and `.xlsm` results remains file-level; beta.14 does not promise sheet or cell navigation and does not invoke an operating-system shell fallback.

If Obsidian cannot open a result file, Kwiry now shows fixed safe copy:

> Kwiry: Obsidian could not open this file.

The raw provider error is retained only by the existing privacy-filtered diagnostic path. The notice does not expose the error, path, workbook name, stack, or private content.

## Verification

The correction passed:

- 1,061 Obsidian tests with one existing skip;
- TypeScript typechecking;
- deterministic production build and 16/16 Gate 5 evidence checks;
- privacy, license, notice, package, corpus, and diff-hygiene validation;
- Linux and Windows Rust CI;
- portable native/WASM parity and rebuild-from-nothing determinism;
- Node 22 and Node 24 FTS5 and full Gate 5 CI.

Regression coverage includes the immediate publication/search race, an intermediate status generation followed by a newer authoritative execution, daemon conservatism, later real invalidation, superseded-query isolation, privacy-safe open failure, and file-only `.xlsx`/`.xlsm` targets.
