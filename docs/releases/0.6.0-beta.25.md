# kwiry-search 0.6.0-beta.25

This release repairs source-local read recovery, makes unreadable-source diagnostics actionable without exposing source data, and distinguishes returned sections from displayed source rows.

## Missing-source recovery

A source that remained unreadable after the immediate bounded retry window could previously be omitted from a cold generation and then disappear from actionable work. An incremental upsert could fail the same way: the pending intent was consumed, the active index remained searchable, and recovery depended on another Obsidian file event, a manual rebuild, profile reactivation, or plugin reload.

Kwiry now retains source-local omissions in a bounded delayed retry queue. Retries reuse the ordinary stable binary-read and incremental-generation path rather than rebuilding the whole vault or falling back to stale Markdown display text. A five-second initial delay backs off per source to a five-minute ceiling, one timer is shared, and each pass is capped by the existing source-batch bound.

A temporarily locked, cloud-placeholder, antivirus-held, or network-share source can therefore join the active generation after it becomes readable even when Obsidian emits no second event. Existing indexed rows remain last-known-good until a successful refresh. A replacement generation that encounters one unreadable source still aborts rather than displacing a complete active generation, but it no longer blocks later ordinary vault events from healing the omission.

Read-window timeout and capacity failures remain systemic safeguards. Kwiry does not overlap an uncancellable timed-out vault read.

## Fixed privacy-safe read causes

Unreadable source diagnostics now distinguish three fixed source-local categories:

- `source_inspect_failed` — Obsidian could not provide stable source metadata;
- `source_read_rejected` — the bounded vault binary read was rejected after retries;
- `source_snapshot_unstable` — the source kept changing or its metadata never stabilized.

Exports contain only aggregate counts and these fixed identifiers. Paths, source content, raw exception text, process messages, query text, SQL, stack traces, and numeric exit or signal details remain outside the diagnostic boundary. Only fixed categorical failure stages may leave the gate.

The existing `source_read_timeout` and `source_read_capacity` stall categories remain separate.

## Truthful grouped-result wording

Backends return matching sections, while the search modal groups those hits into source rows. The status now names both dimensions explicitly. For example, seven section hits grouped into five visible notes are reported as:

> 7 returned sections — 5 sources shown; search window complete.

If the configured source-row limit omits sources already observed inside the returned section window, that exact local omission remains separate from candidate-window completeness. Kwiry still does not infer sources below the bounded 100-section response or promote candidate counts into corpus totals.

## HTML source identity

HTML `<title>` metadata remains searchable and strongly weighted, but an HTML source row now displays the vault filename as its primary identity. For example, `site/index.html` is headed `index.html` rather than replacing the filename with the document title.

## Compatibility

This patch does not change lexical ranking, extraction behavior, source identities, or persisted/index transport contracts:

- Worker protocol remains 13;
- plugin cache schema remains 12;
- source-preparation schema remains 10;
- HTML extractor identity remains version 2.

No forced reindex is required. An existing unreadable warning will be retried automatically after the plugin updates; a manual rebuild remains available but is no longer the only recovery path.

## Verification and publication boundary

Automated verification covers cold and incremental omission recovery, replacement-generation retention, bounded retry/backoff and disposal, clean-cache export after recovery, fixed diagnostic cause validation and privacy, grouped section/source wording, HTML filename display, typechecking, production build, and the complete one-worker plugin suite.

The real Obsidian WebDriver/X11 candidate gate remains part of the protected release workflow. BRAT publication still requires the immutable candidate handoff accepted by the publisher workflow.

## Install

After the protected candidate and publisher workflows complete, install or update through BRAT using repository `cybersader/kwiry`, or use the release archive attached to `0.6.0-beta.25`.
