# kwiry-search 0.6.0-beta.31

This release prevents broad lexical searches from failing when a matching candidate carries structurally valid heading navigation metadata that cannot fit the public search-hit bounds.

## Search reliability

The in-plugin index continues to retain complete canonical heading paths for source identity, indexing, ranking, cache export, and cache restore. Public results preserve an exact heading path when it fits the existing response limits. When a structurally valid path is too deep, contains an overlong component, or otherwise cannot be represented safely, the result now carries an empty heading path and opens at the source level instead of failing the entire search.

The daemon client applies the same publication rule for compatibility with existing daemon responses, keeping in-plugin and daemon navigation behavior aligned.

## Corruption and compatibility

Malformed heading JSON, non-array values, and arrays containing non-string elements remain invalid. The repair does not truncate authored headings, invent section targets, drop searchable sources, or change candidate collection and ranking.

Worker protocol 15, cache schema 12, source preparation, chunk identity, format identity, query binding, candidate-window semantics, diagnostics schema, and persisted index layout are unchanged. No migration is required; versioned disposable cache data may rebuild under the existing upgrade behavior.

## Privacy

The diagnostics and search-response privacy boundaries are unchanged. No query text, source identity, path, excerpt, SQL, execution plan, arbitrary backend message, stack, credential, or token is added to diagnostics.

## Verification

Automated coverage exercises public-boundary values, over-bound source admission, fresh in-plugin search, canonical cache export, restored search, production Worker execution, daemon response normalization, and continued corruption rejection. Existing Node 22/24, package privacy, deterministic evidence, license and notice, real-host WebDriver, immutable candidate, and protected publishing gates remain in force.
