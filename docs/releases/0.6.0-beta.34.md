# kwiry-search 0.6.0-beta.34

This release improves exploratory recall for sparse standard result sets, prevents rapid typing from accumulating obsolete synchronous searches, stops retrieval once the candidate window is full, and discloses when the fixed source-discovery window may hide additional sources.

## Sparse-result exploration

Long ordinary queries remain precise first. When prior authorized standard lanes reach fewer than 20 distinct sources, shared Rust now activates the existing bounded exploratory partial-coverage lanes. Exactly 20 standard sources suppress exploration. Multiple chunks from one source count once, and unauthorized candidates never contribute to the threshold.

Required identifier anchors remain mandatory. Useful optional terms remain one flat alternative group requiring at least one match; no combinations or power-set expansion are generated. Standard proofs continue to rank above partial proofs, and filename, title, and alias partial evidence continues to rank above body-only partial evidence.

## Bounded typeahead and retrieval

Interactive search now uses a 100 ms trailing-edge scheduler before the backend boundary. At most one backend request is active and one replaceable latest request is pending. Superseded pending searches resolve stale, while an already-active synchronous Worker search may finish before the latest due request is dispatched.

Native and in-plugin retrieval stop executing later lanes after retaining 512 unique candidates. The lane that fills the window retains its existing 256-row raw limit so duplicates from earlier lanes cannot reduce unique recall. A saturated individual lane below the total window now reports unknown completeness rather than incorrectly claiming that the 512-candidate limit was reached.

## Source-window disclosure and diagnostics

When the fixed 100-section source-discovery response window comes back full, the search status states that additional sources may be unobserved. This remains independent from the exact count of already-observed sources omitted by the source-row display limit and from candidate-window completeness.

Diagnostics carry this as a closed boolean alongside bounded aggregate execution evidence. They continue to exclude query text, terms, source identities, paths, excerpts, SQL, raw plans, arbitrary backend messages, credentials, and tokens.

## Compatibility and migration

The internal lexical query-plan schema advances to 11 and the FTS5 match-plan schema advances to 10. Worker protocol 16, cache schema 12, persisted index layout, source preparation, format identities, public daemon response bodies, ranking points, and mode behavior remain compatible. No migration is required; disposable cache data remains valid.

## Verification

Verification covers the full daemon workspace, portable Rust and WASM targets, native/WASM byte parity, authorization-before-retrieval, 19-versus-20 source activation boundaries, deterministic candidate closure, FTS5 trace accounting, typeahead scheduling, source-window disclosure, diagnostics privacy, production packaging, and a pinned real-Obsidian Selenium gate. The real-host gate confirmed zero status or sibling movement and emitted aggregate-only evidence.
