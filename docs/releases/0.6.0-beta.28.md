# kwiry-search 0.6.0-beta.28

This release adds privacy-safe search-miss evidence to diagnostics and compacts the field-control help in the search modal.

## Search-miss diagnostics

Diagnostics exports now include bounded categorical evidence for source generation and lexical execution. The export can distinguish cases such as unavailable evidence, explicit bypass, empty candidate generation, zero-observation execution lanes, candidate saturation, collection-cap discards, and retained-candidate truncation.

Source-generation evidence reports document, chunk, zero-chunk-source, and format counts. Lexical-execution evidence reports bounded probe, lane, field, observation, candidate, duplicate, saturation, and truncation counts. Search terminal records capture the evidence atomically so the exported outcome and evidence cannot disagree.

The privacy boundary remains closed: diagnostics do not include raw queries, source identities, paths, excerpts, content, SQL, raw execution plans, arbitrary backend messages, stacks, credentials, or tokens. Invalid execution plans produce the fixed `plan_rejected` category rather than detailed binder errors.

## Compact field-control help

The search modal retains the field-syntax control introduced in beta.27 but presents its guidance in a compact popover instead of reserving a large permanent vertical block. The supported syntax and mode restrictions are unchanged.

## Compatibility

This release changes transient diagnostics and Worker response contracts:

- diagnostic export schema advances to 2;
- Worker protocol advances from 14 to 15;
- plugin cache schema remains 12;
- source-preparation schema remains 10;
- source identities, chunk identities, extraction behavior, and persisted index storage are unchanged.

No forced reindex is required. Existing disposable native and in-plugin indexes remain compatible.

## Verification

Automated coverage includes exact diagnostic schema validation, atomic terminal records, zero-chunk source accounting, bounded lexical-execution aggregates, backend evidence mapping, privacy-safe plan rejection, modal diagnostics, package privacy, deterministic release packaging, and the complete Node 22 and Node 24 Gate 5 lifecycle.
