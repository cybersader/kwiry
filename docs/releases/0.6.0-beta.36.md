# kwiry-search 0.6.0-beta.36

This release adds native whole-file hover previews to search results and preserves index freshness across lifecycle recovery.

## Native file previews

Enable Obsidian's core **Page preview** plugin, then hold `Ctrl` on Windows/Linux or `Cmd` on macOS while hovering a source or section row. The default modifier requirement follows native Page preview settings; its Kwiry Search preference can also allow previews without a modifier.

Both row types request the whole file, rather than a heading, PDF page, or sheet. Preview rendering and supported formats belong to Obsidian. Hovering does not run another search, open a file in the main workspace, or change the selected result.

Native popups now sit above the search modal and remain usable when the pointer enters them. Owned previews are dismissed when results rerender, the query changes, the modal closes, the backend is invalidated, or the plugin unloads. With Page preview disabled, search remains available without a popup.

## Freshness and recovery

In-plugin lexical indexing now requests an authoritative inventory for folder lifecycle changes and keeps that obligation until a reconciled generation is committed. Aborted replacement builds retain the active generation and preserve rescan work, including changes arriving during publication.

Unreadable-source recovery retains retry backoff across replacement attempts and stops retrying healed or deleted paths once a completed inventory proves they no longer need retries. Historical omission warnings remain until a complete replacement is published.

The search modal retains settled source/section evidence during unavailable status so local navigation does not issue a new backend search. Opening still requires currentness, and a recovered searchable generation is compared with the held results even when that generation was already observed during an earlier request.

## Compatibility

The minimum Obsidian version remains `1.7.2`. This release changes no query-plan, rank, Worker protocol, cache, source-preparation, or chunking schema. It publishes the Obsidian plugin, not a daemon binary.

## Verification scope

Local validation covers the client suite, typecheck, production build, deterministic artifact evidence, source and package privacy, release identity, and license/notice checks.

The native hover witness uses actual WebDriver keyboard and pointer input in an isolated Linux host with synthetic Markdown. All 24 cases pass on the versioned plugin with pinned Obsidian `1.13.7`, Electron `43.3.0`, and ChromeDriver `150.0.7871.212`. It covers modifier timing, source and section whole-file previews, popup stacking and pointer entry, lifecycle dismissal, native preference changes, and Page preview disabled. Backend invalidation and plugin unload are explicit fixture lifecycle actions, not simulated user input.

This does not establish native macOS `Cmd` behavior, native previews for other file formats, semantic runtime behavior, OpenClast integration, daily-drive acceptance, or owner roadmap acceptance. Local checks are not full tag CI; publication still requires the exact-tag CI and formal real-host candidate release gate.

## Install
